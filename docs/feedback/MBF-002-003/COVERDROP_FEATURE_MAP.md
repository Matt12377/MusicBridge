# MBF-003 CoverDrop 完整功能映射

固定来源是 CoverDrop `93fa28f3245da50cf9b5341e0df1466fa4f6a0e7`；MB 对照基线是 `479e746bb7106a4dac158fe616290220de03a53a`。源文件只从固定 Git 对象读取，没有读取或修改 CoverDrop 脏工作区。此映射包含 35 个原可见功能切片、1 个 MB 既有保留切片和 1 个固定源不存在项。细节与机器身份见同目录 JSON。

这是源码范围核对，不是功能通过或真实使用验收；表中 MB入口/缺口以479基线为准，新模块/API/当前定向证据见 `WORKBENCH_IMPLEMENTATION.md`。报告中的八行定向发现只作为输入，不能替代完整范围。实现后需要绑定最终提交分别记录局部行为测试、构建、真实 App、源音乐/输出和 Owner 复试。本线主代理产具体提案，调度 Root 审界，MusicBridge V3.9 在004封板后串行装配共享最终实现。

## 核对结论与保护边界

- 原筛选有全部加七类，除需求强调的六类，另有“track 音轨”。缺封面与未知、标签失败与缺字段、散落音频与无发行关系均不能混为一类。
- 原聚合是豆瓣 + iTunes；网页来源为豆瓣/Bing/Google。MB 基线的 MusicBrainz/CAA 与 Commons 不能代表原完整来源已迁入。
- 原 AI 实装含 Ollama、vLLM 和云端 OpenAI 兼容 API/钥匙串。三个后端完整保留；云端沿批准的桌面保险库接线，不迁旧 Keychain、不发真实付费请求。未接入能力仍须作为完整迁入缺口记录。
- 原 AI 返回后立即更新展示和快照。MB 的新工作台必须展示候选、理由和字段变化，预览后由用户明确应用；手工字段表单不能替代模型建议。
- 原 `splitCueSheetInPlace` 在专辑目录生成音频并写输出标签；本次改为独立输出，源不变。CUE 规则移植、段落投影和段落播放保护都不等于文件分轨交付。
- 原 `renameLibrary` 只更改库显示名，原 AudioTagWriting 只服务生成的分轨文件；固定版本没有通用源标签编辑/音频改名移动 UI。MB 012/013 已有链必须保留，继续走源写资格、精确计划、资源锁、备份、journal、回读与恢复。
- 固定来源没有歌词入口或装配服务；后来历史记忆及脏源码不纳入原93fa范围。MB现有歌词链保持原样。
- 普通浏览、查候选和选图均不创建发行；没有 edition 时可走候选，明确应用时才由作者建立安全 MB 关系。所有未接入动作显示不可用；未知应用只查询原 command，不重签重放。

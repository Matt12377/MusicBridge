# 本地音乐库与常驻 Rust Worker

本轮代码位于 `worktree/v4`，分支 `codex/v4`，起始 HEAD 为 `f459c46525855e87e1d8ee68388e8ea21ab04653`。保留该工作树原有播放器和开发入口改动，没有提交、启动应用或操作真实音乐库。

## 用户操作链

- 本地音乐与资料库整理共用根目录、扫描任务、专辑曲目和封面缓存。
- 根目录成功读取且没有任何音乐库时，页面显示首次添加入口：选择目录、确认加入、自动启动持久扫描。设置中始终可以添加和管理资料库。
- 已有目录但尚无曲目时显示实际扫描进度、暂停或错误；普通音乐库页面不重新出现此前移除的管理工具条。
- 分批入库后刷新专辑列表，封面按可见范围加载；目录图片优先，缺少可用目录图片时读取内嵌封面。缺图保留占位，通过设置里的整理入口手动或批量补图，不自动联网匹配。
- 重启先显示已经入库的结果和缓存封面。系统中断的任务在原目录在线、许可及版本有效时自动继续；主动暂停的任务保持暂停。

## 扫描与并发

采用 CoverDrop 的分阶段处理、受控并发、封面复用和连续小批提交思路。目录发现片段先持久化，每个文件保留对应 frontier；当前普通发现片段最多 64 项，CUE 扫描复用已记录的发现清单。历史没有清单的 CUE checkpoint 保留兼容恢复路径。

目录调度窗口默认 12，实际音乐文件读取共享 2 个槽位，并继续受原 Core 读取许可控制。这不是 12 组、每组 50 首并行。只提交原顺序中已完成的连续前缀，达到 16 项或 250ms 时尝试提交；目录、文件、任务版本及读取身份核对继续保留。checkpoint 不越过未完成项目。

音频标签解析和内嵌封面读取调用常驻 Rust Worker。普通扫描与浏览共享 DatasetOwner 的池，最多 2 个进程；Main 中用户主动导入图片使用独立池，最多 2 个进程。CUE 文本 sidecar 仍保留原有界 JS Worker，CUE 技术与来源约束不因迁移而扩大。

Rust 只接收文件长度和有界读取请求，不接收音乐源路径、数据库连接或 Node 文件描述符。Node 继续持有源文件句柄与许可，任务实际结束后才释放。取消、超时或协议异常会终止对应进程，并等待进程关闭及在途读取结束；健康进程在正常任务间复用。

标签读取支持原格式开关与预算，解析使用固定版本 Lofty。图片使用固定版本 image，保留 PNG/JPEG/TIFF/WebP 结构和尺寸准入，一次解码生成详情展示图与 512px 网格图。TIFF/WebP 另生成原尺寸 JPEG 兼容副本。网格和详情图一起持久缓存；旧缓存继续可读，超出网格解码预算时沿用原有界缩略图缓存。

可选的完成快照仍有原 10,000 条事实预算；SQL 曲目、专辑、任务与 checkpoint 独立持久化，正常分页和断点恢复不依赖该附加快照。快照失败单独记错，不将已经完成的扫描记为取消。

## 终端日志与延迟

常开日志前缀为 `[MB_LIBRARY_OPERATION]`。Renderer 的受信主框架日志、DatasetOwner/Core 日志及 Rust 阶段诊断汇总到开发终端，不需要开启 trace 环境变量。

日志覆盖添加目录、扫描发现、标签解析、文件读取、封面处理、缓存命中与写入、分批提交、暂停恢复、专辑分页及图片加载。字段按阶段包含 `elapsedMs`、`queueWaitMs`、`readMs`、`parseMs`、`commitMs`、计数和固定失败码。默认 250ms、图片处理 100ms、缓存写入 50ms 为慢操作阈值，命中时输出 `slow:true`。这里记录延迟，不人为增加等待；250ms 提交定时器用于及时展示小批结果。

不记录音乐源路径、标签内容、图片字节、凭据或第三方原始错误栈。逐行转发有闭集字段与长度约束，避免普通 SDK 输出混入诊断。

## 开发入口与交付边界

现有 Core/桌面开发构建入口已接入 Rust 构建、staging 和二进制 SHA 校验。Rust 编译缓存按工作树身份及目标保存在外置卷持久目录，构建日志和临时文件也采用外置卷策略；生成资源不会从其他工作树复制归属标记。原生 Worker 协议、依赖、输出清单和边界详见 `native/media-worker/README.md`。

初次交付按要求仅提供代码，没有执行构建、类型检查、自动测试、视觉验证或真实音乐库运行。随后 Owner 报告构建失败并授权构建测试，验证记录见下方。源码接入不代表已测得真实音乐库扫描提速或通过运行验收。

# ADR-009：V3 收藏库存存储

状态：TASK-049 采用；音频资产和归档保留策略 F-01 不在本决策内。

## 决策

库存由 Bridge Core 内的 SQLite 仓库管理，文件为 Main 注入的私有 data 目录下 `collection.v1.sqlite`。采用当前 Node/Electron 运行时内置的 `node:sqlite`，不新增原生 npm 扩展或改变 lockfile。Renderer 只通过有界业务 IPC 读写，不接触文件路径和 SQL。

型号描述以品牌、型号、版次、年份、介质和类型确定身份；时长独立为 SKU。同一版次的 60/90 分钟归组展示，但批次及可录容量分别保留。待识别信息不会自动升级为已确认信息。

Inventory Lot 保存未开封、已拆空白、旧录音待登记和未分类数量。只有需要逐盘管理时才从池中转出一盘，分配永久 Physical ID。总量等于剩余池数量加实体数量，两个视图不能增加实物总量。

所有变更使用 `BEGIN IMMEDIATE` 事务：余额、序列、实体和追加账本一起提交或一起回滚。每个业务命令带 UUID；同命令同内容返回已保存结果，同命令不同内容拒绝。账本禁止更新和删除。提交失败不自动换新命令重试。

已录音与未知状态不能预留；封存保护、最低保留数与仅收藏策略在 Core 再次检查。状态修改使用 revision 冲突检查。取消预留恢复预留前状态，不更改实体编号。当前不开放擦除、处置、归池或真实录音完成。

## 存储与恢复边界

- 使用外键、严格表、WAL 和同步提交；新 schema 在事务中创建。未知 schema 或损坏文件报告不可用，保留原文件，不自动清空或降级成空库。
- 数据库以 `0600` 创建，父目录由 Main 以私有权限创建；拒绝数据库、WAL/SHM 和直接父目录符号链接。不把此检查视作对被恶意替换的整个文件系统的保护。
- 数据库延迟打开，因此库存故障不会阻止 V2 播放启动。公开错误仅包含安全业务码和中文提示。
- UI 保存回执未知时保留原命令，只允许原请求重试；当前表单被锁定，明确区分“正在保存”“未确认”“已保存”。账本幂等结果跨进程重启保留。
- UI 自动测试使用独立临时 userData，真实 SQLite 加合成业务输入；不读取用户库存、照片、账号、音乐文件或硬件。

## 替代方案

JSON 快照适合此前的小型歌词映射，但库存需要跨表转移、唯一序列和不可重复账本，继续扩展快照会增加恢复和并发控制成本。SQLite 将这些约束放在同一事务边界内。此选择不把后续音频文件存入数据库；照片、原版实物、源验证、录音历史和备份由后续任务迁移扩展。

## 验证

仓库测试覆盖幂等、独立连接与进程并发、事务中断恢复、未知 schema 保留、符号链接拒绝、时长归组、状态保护和分页。正式 Electron 验证从录入到完全退出再启动，并注入“写入已提交但回执丢失”的受控故障检查重复计数。最终结果以 `reports/TASK-049_RESULT.md` 为准，不等同完整 PRD Gate C 或 Owner 验收。

# ADR-040：只读快照版本探测与显式刷新路由

状态：RUST-003 开发中；生产默认 Node。

RUST-002 的只读快照是导出时刻的事实，Node 后续写入不会修改它。因此可选读取必须证明版本仍适用，不能以进程还活着作为新鲜证据。先选择按读取探测，比引入跨 208 命令和异步协调器的推送协议更容易核验遗漏写入的风险。

在 Node 唯一所有者的同一 SQLite 连接比较 data_version 和 total_changes；前者捕捉其他连接提交，后者捕捉本连接的变化。使用实例内 UUID 令牌封闭底层计数，禁止跨库/实例比较；版本化导出在完整同步原子读取两侧验证 stamp，失败不配对不同事实。Rust 仍不获得路径、SQL 或写入权限。

可选路由借用既有已 boot Owner。初始继续 Node；显式刷新排空旧 child 后才建立新 child，发布前再探测。刷新、失效和关闭同步提升 generation，迟到候选只清理，迟到读取拒绝。候选在原生 prepare/boot 之前登记到路由，即使工厂尚未成功返回便失败，也保留其退役结果；关闭失败阻止新 child，不以 SIGKILL 调用冒称已退出。潜在写入在途不建立快照，未知写入回执原样保留，任何路径不自动重放。

Rust 读取前后均取版本。前置变化可选择尚未发出的 Node 读取；后置变化不能交付旧结果，也不能悄悄重读。公开 readContext 由 Node 处理；已审定纯收藏读取 collection.list/detail/copy/photo 的 Node 结果也受代次围栏。其他命令保守按潜在写入失效后仅在 Node 执行一次，保留真实回执，不按名称推断全部 208 命令的副作用。内部状态可说明路径、刷新与故障，但不进入 Renderer 公开合同。

代价是每次读取的两次版本探测及刷新完整启动。必须把这些成本与原 Node 查询一起测量；如果收益消失，保留默认 Node，并由测量决定下一处计算热点，不能用裸 Native 查询时间证明产品提升。完整合同见 [只读路由 v1](../contracts/rust-readonly-router-v1.md)。

# ADR-021：转换谱系与输出回读（草案）

状态：Owner 已确认固定 FFmpeg + SWR；内核、持久化、桌面明确确认与固定源码构建已接入，本地包合成 Gate 已通过，发布及输出认证仍未完成。本文不批准 FFmpeg 分发或正式录音。

## 已实现的后端无关边界

转换计划分别保存源文件 Hash/大小/容器帧证据、固定输出格式、转换器二进制与构建 Hash、组件版本和处理参数。参数是适配器生成的谱系，不是 Renderer 可执行参数；后端仍须校验自己的精确参数集合。路径、额外命令和认证标记不能进入公共合同。

源必须无损并有冻结帧数。整数位复制只允许已知 PCM/FLAC、同采样率/声道/位宽，且不使用 SRC 或 dither；浮点不能只凭同位宽声明整数位复制。同率解码必须保留全部帧，异率允许最多一个输出帧的整数边界差；这是预先定义的合同限制，不是实测 SRC 精度。Core 后端还须核对真实解码、完整消费输入、计划 Hash 与输出字节，不能只提供退出码。

`inspectConversionOutput` 仅接收上层持有的普通文件句柄，返回实际大小、帧数、PCM 起点及整文件/PCM 各自 Hash。它不产生完整转换回执，不证明解码过程、音质或设备认证。回读保持只读，核对文件前后身份，限制墙钟与单调时钟时间；短读补齐，异常返回公开错误码。

输出当前限定 RIFF/WAVE、mono/stereo、8–384 kHz、16/24/32-bit 整数或 32-bit IEEE 浮点。扩展格式须有准确 GUID、完整有效位宽和明确 mono/stereo 声道位置；不猜测 DIRECTOUT 或低有效位宽。浮点需要一致的 fact 帧数，并逐样本拒绝 NaN/Infinity；有限的超满幅样本不被裁剪或归一化。RF64、64-bit 浮点输出及其他布局仍未支持。旧整数 PCM 复制入口继续拒绝浮点、扩展格式和 fact，不改变历史配方范围。

扩展格式中容器位宽、有效位宽与声道位置是不同字段；本文选择的执行输出子集比通用格式更窄，依据见 [Microsoft WAVEFORMATEXTENSIBLE](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ksmedia/ns-ksmedia-waveformatextensible)。

源探测另修复了错误接受 16-bit IEEE 浮点的问题；32/64-bit 浮点源的容器帧探测保持可用。这仍不是逐帧解码证据。

## 已实现的转换内核

FFmpeg 8.1.2 / libswresample 6.3.102 使用 Core 私有固定清单；启动前后核对可执行文件、配置内依赖的完整 Hash 和文件身份，版本输出也需精确 Hash 匹配。不搜索 PATH，不提供 Renderer 可执行路径或任意参数接口。该清单核验不等于完整分发依赖、签名或许可准入。

FFprobe 先完整解码并累计实际源帧数；源采样率和帧数必须与冻结证据完全一致。转换另开已核验的只读 FD，避免探测共享文件偏移影响输入；输入/输出通过 FD 传入，不把路径加入 FFmpeg 参数。子进程失败、任何错误输出、取消或超时均不能返回成功，取消等待进程实际关闭。源只读租期覆盖输出回读和结束时构建检查；输出回执返回前再次核对文件身份与修改时间。

V2 配方独立于旧版 PCM 配方。预览记录每条原输入及转换参数和允许的总帧数范围，实际转换回执决定最终段起止帧。声道映射按每个源明确记录，其余输出参数一致。Direct 只拼接已核验的转换 PCM 字节，按执行采样率插入精确数字零；不二次 SRC/dither，不裁剪首尾静音。Prepared Derivative 只接一个完整 Render 的转换回执，不加入 Gap，不改写原件或冻结版本。

## 持久化与桌面边界

V2 Direct 明确保存逐曲转换文件和逐面成片，两者都进入独占目录、写盘预算和发布清单；未校验的部分产物不会成为资产。PREP Derivative 从实际保留原件探测输入规格，输出独立文件，保留原件谱系及授权检查。发布后提交中断仅核验已有产物并补交，不重读 Direct 用户源、不重放转换；损坏、撤权或不完整产物仍不可用。取消和失败不自动删除文件。

SQLite 表结构保持 schema 12，配方及清单 schema 2 负责区分新记录；旧 V1 合同和清单保留读取能力。公开 API 只增加明确的执行模式，不接收可执行路径或自由参数。Core 运行时可由受信任组合层注入固定转换器，产品启动从固定资源目录读取清单，以编译期 Hash 和逐文件完整 Hash 核对；无包或校验失败时只禁用转换，不能自动搜索或启用系统 FFmpeg。桌面预览展示计划参数与构建身份，实际文件回执仍由 Core 核验。见 `reports/TASK-061_INTEGRATION_CHECKPOINT.md`。

## 固定本地构建与打包身份

官方 FFmpeg 8.1.2 源码经签名指纹和压缩包 SHA-256 核验。配置关闭 GPL/nonfree/version3、网络和第三方自动发现，只启用当前音频输入/输出子集与 FD 协议。共享依赖闭包为 5 个 FFmpeg dylib 与明确的 Apple 系统库；无 Homebrew 路径。应用附带对应源码、许可、配置与署名材料。本地核验不替代 [FFmpeg 分发许可要求](https://ffmpeg.org/legal.html) 的法律审查。

原生包由独立构建脚本生成到忽略目录，不提交二进制。Vite 同时生成 Core 常量和打包身份快照。Core 引导先安装消息监听，再在收到端口后异步核验转换器，避免启动消息丢失。常规合成测试保留无后端模式；显式原生 Gate 才在合成运行时注入固定包。

electron-builder 打包前核对编译快照、完整二进制集合及源码/许可材料。当前只允许关闭签名自动发现、显式无 Developer ID 且启用 Fuses ad-hoc 重签的 arm64 本地包；发布签名会改变二进制 Hash，需另建先签名后锁定的流程。包完成后须再次核对 Hash 和签名并实际启动，不能用打包退出码代替运行证据。ASAR、安全 Fuses 与 Renderer 隔离不降低。

两个不同构建的浮点输出不承诺逐字节相同；构建 Hash 是执行谱系的一部分。本次整数参考输出逐字节一致，浮点样本观察到 20 个近零差异，最大绝对差 3.47e-18；同一固定构建重复输出字节一致。该结果只覆盖已测试合成样本，不构成通用误差上限或听感认证。

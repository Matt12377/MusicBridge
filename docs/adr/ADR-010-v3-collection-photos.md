# ADR-010：实物照片展示副本与库存数据库共存

- 状态：TASK-050 本地实现决定，真实照片与 Owner 视觉验收待执行。
- 基线：ADR-009 的库存模型、事务账本和永久单盘身份。
- 范围：型号/单盘实物照片、收藏墙代表图；不扩大到音频归档或参考目录抓取。

## 决定

用户通过原生文件选择器逐张选择 PNG/JPEG。Main 只读所选普通文件，不遍历目录，不接受符号链接，不改原文件。读取前后核对文件身份、长度和修改时间；输入上限 25 MiB、4000 万像素、单边 16000 像素，先检查格式头，再由 Electron 解码。

展示副本等比例缩到最长边 1200 像素，编码为 JPEG 85，最多 1 MiB。原图不作为档案导入；Renderer 不获得源路径，数据库不保留文件名或原图 EXIF。UI 显示的是展示副本，不承诺恢复原始照片。

每个型号最多 24 张展示照片，照片可选绑定已有 Physical Copy。添加型号照片不会分配实物编号，也不会改变库存数量。照片归属型号与单盘时必须一致。同一型号、单盘归属和相同展示字节重复导入复用照片身份；不同归属不会被内容去重混为同一实物。

## 存储与迁移

- Schema 1 → 2 增加 `collection_photos` 和 `collection_featured_photos`；旧库存、序列、保护策略、账本不改写。
- JPEG BLOB、SHA-256、尺寸与归属在同一 SQLite 事务中提交，避免这类小展示资产引入文件系统/数据库双提交窗口。
- 新增、代表图和删除操作沿用稳定命令 UUID、幂等结果与不可修改账本；账本只留身份及 Hash，不写图片 Base64。
- 首张照片默认成为代表图；明确选择覆盖默认。移除代表图后回退到尚存的第一张，最后一张移除后回到缺图状态。原文件不删除。
- 迁移在写锁内重读 schema 版本，失败回滚。未知版本仍拒绝打开而不清库。
- 照片读取核对内容 Hash；损坏仅返回有界读取错误，不能把库存伪装成空库。

取舍：此方式减少独立文件生命周期，但数据库体积会随照片增长。上限和有界读取控制单次请求，不代表整个库总容量固定。未来大体积原图或音频必须使用独立归档协议，不能套用此方案或宣称 Gate E 已通过。照片副本将纳入后续一致性数据库备份。

## UI 与接口

新增文件选择、添加照片、按照片 ID 读取、代表图/删除四个公开业务方法；Core 不接触所选源路径。图片以有界 JPEG data URL 返回，继续使用既有 CSP，不增加任意本机文件协议或外部图片来源。

收藏墙保留型号/版次及数量，支持关键词、品牌、年代筛选和分页。筛选先于 SQL 分页；关键词按字面子串匹配，不把 `%` 解释为通配符。Vue 响应式筛选对象转换为普通数据后再进入 IPC。

详情提供大图、代表图选择、移除二次确认与重新加载。图框使用 `object-fit: contain`，不拉伸裁切；图片失败不移除实物记录。旧录音内容尚未补录时明确标记，正式实体音乐关联由下一任务接入。

## 并发回归修正

现有双进程测试在首次 `PRAGMA user_version` 读取复现 `SQLITE_BUSY_RECOVERY`（261）。原代码在首次读取之后才配置 busy timeout。现在创建连接后、读取版本前先设置 1000 ms 有界等待；其他写入规则不变。

保留了原失败日志，新增另一进程持有短暂锁的确定性测试，并继续验证并发重复命令只记一笔。超时仍明确失败，不无限重试、不换命令或清除数据。

## 大图关闭事件

原生 dialog 的 close 事件异步投递。完整 E2E 捕获快速关闭、切换窗口尺寸再打开时，上一轮通知清空当前 preview 的竞争；页面仍显示打开的弹窗但没有图片节点。现在只在 dialog 仍关闭时清理 preview。已有正式 UI 测试增加延迟 close 通知注入，保留真实导入、图片读取与弹窗交互。

## 验证边界

自动测试使用合成图片和隔离目录。原生解码、缩放、Main/Preload/Core/SQLite、正式 Renderer 与 Electron 重启均可自动取证；文件选择由测试代替，不能作为用户真实照片体验的证据。

任务报告分别记录自动 Gate、真实照片、Owner 验收与 Git 状态。F-01 执行音频保留策略、TASK-049 跨重启未确认操作 outbox、真实 Roon/录音与完整 A～E Gate 均不因本任务完成而结束。

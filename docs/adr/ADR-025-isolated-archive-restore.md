# ADR-025：隔离恢复候选与不可信历史索引

状态：TASK-065 本地候选。当前不激活 Runtime，不关闭完整 Gate E，也不表示 Owner 已接受。

## 决策

恢复首先验证 TASK-064 的备份包，检查 SQLite、Manifest、实际声明内容字节和引用闭包。随后向新建的隔离目录复制数据库和内容；原数据库、原备份、既有候选均不覆盖。不能绕过完整验证只读取完成标记。每次恢复需要明确确认与稳定任务 ID。

恢复数据库中的库存、照片、不可变版本和操作账本保留，不删除历史触发器，也不改写不可变路径事实。可变授权层的 Source Roots、Preparation Destinations、Prepared Selections、Archive Roots/Candidates 全部撤权；正在执行的源/版本/工作区/Render/执行任务改为 interrupted。这样旧 inode 和绝对路径不会被误当作新机器的可用权限。

恢复收据 `Restore.json` 包含源备份 ID/Manifest Hash、原始数据库摘要、隔离后数据库摘要、内容范围与引用索引。所有文件再次核验后写 `RestoreComplete.json`。候选状态始终是 `isolated-pending-activation`。

## 重试与冲突

相同任务 ID 已存在时，只验证原候选与源备份身份，禁止再次覆盖写入。候选库有新写入、Hash 变化或权限状态改变时显式拒绝，保护新数据。候选仅用于只读核验；使用正式仓库打开它可能修改 journal 元数据，不能再把它当作未改变的原候选收据。正式激活后的重试/备份流程由下一任务独立定义。

失败/取消留下没有有效完成收据的隔离目录，不自动删除，不访问源备份之外的历史路径。Core 内部能力接口要求调用者提供当前受保护目录集合；原生授权和持久命令工作流在 TASK-066。

## 无数据库时的基本索引

支持两种已授权布局：备份包的 `manifests/objects`，以及原生 Archive Root 的 `Operations/<id>/Manifest.json` 和 `Objects`。后者先验证 Root owner 和目录能力。

严格检查 Manifest schema、操作 ID、版本 ID、文件角色、名称、Hash/大小及重复引用；只读核验实际对象。结果是 `needs-review`：

- 字节可验证仅标为 `bytes-verified-history-unverified`。
- 缺失或损坏为 `quarantined` 并返回结构化问题清单，不移动、删除或改写共享对象。
- 库存账本、完成录音、冻结版本事实、Profile、人工确认和目录授权均标记缺失，不能由文件名补造。
- 重建是只读候选索引，不自动注册成正式业务对象；持久审核与 UI 在后续工作流承接。

元数据恢复不会声明音频已恢复。原生 Root 的恢复索引也不依据 FINALIZED 文件名就宣称正式录音完成。

## 后续激活

TASK-066 仍须实现原生选择与授权、当前根位置绑定、隔离库明确激活和后台命令恢复。旧归档 identity/data 有不可变约束，不能通过删除触发器迁移历史路径。尚未完成激活后再备份/恢复验证，因此完整 E-12/E-13 保留；E-14 目前是基本候选索引，不是完整历史重建。F-01 未决，不引入删除或正式录音政策。

## 验证

先运行缺接口 RED；隔离恢复、重复收据、候选更新冲突、元数据包、未确认/重叠/损坏拒绝、复制失败、取消、PREP 历史与授权撤销、运行任务中断。另覆盖无 DB 的包/原生 Root 索引、重复只读检查、损坏/缺失 Quarantine、非法 Manifest 与取消传播。自查补两项 RED：原生 Root 布局，以及重算顶层 Hash 不能掩盖无效原数据库描述；修复后再运行全量 Gate。

故障测试为隔离合成数据/受控复制失败；不宣称真实拔盘、断电、真实 Logic 或 Owner 恢复验收。单应用本地文件系统范围与 TASK-064 相同。

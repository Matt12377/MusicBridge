# ADR-020：版本化录音参数与执行资产发布

状态：TASK-060 本地实现；正式录音、保留策略和 Owner 验收仍未完成。

## 背景与范围

PRD v0.3 第 56～59 节要求复用有序设备链与默认参数、本次仅覆盖变化项，并使历史录音脱离以后修改的默认值。TASK-059 已有固定格式与 PCM 编译内核，但没有持久化执行任务、发布恢复和桌面入口。本阶段连接这些能力，不创建 RecordingPlan 或 Attempt。

## 参数身份

- `RecordingProfileVersion` 保存有序设备/连接、默认 NR、校准、电平、手动预卷、介质兼容及显式执行格式。编辑产生新 UUID 与递增版本，父版本和内容 Hash 保留；禁止原地修改历史版本。
- `RecordingSessionSettings` 按草稿保存所选 Profile 版本、修订号和 Overrides。字段缺席表示继承，`null` 表示明确未设定；临时链覆盖整个有序链。没有默认 Profile 的自动迁移。
- Profile 与 Session 分别使用命令账本、CAS 和事务保存；原命令回执丢失后重试不产生新版本。每模板至多 100 版本、至多 100 模板。
- 执行提案解析并保存当次 Profile、Overrides、有效参数和完整 `ExecutionFormat`。Profile 后端名称与版本只代表用户填写的计划，不是已注册后端、设备认证或输出就绪证据。
- 手动预卷只属于操作参数，不再写入 Lead-in、Gap 或原始 Render。正式 `RecordingProfileSnapshot` 仍须由后续 RecordingPlan Freeze 建立。

## 执行准备与发布

Main 复用原生目标目录授权，Renderer 仅传公开编号、修订与确认命令，不传源路径或可替换配方。Core 从 Frozen M/L、仍有效的介质预留和参数版本重建提案；不读取当前草稿中的替换来改写旧版本。

Direct 在确认后排他建立 `MusicBridge-Execution-<jobId>/Audio`，逐非空面生成整数 PCM WAV。Prepared 引用 Frozen PREP 对应的独立保留原件，完整校验实际 WAV 后只发布清单，不复制、不再插入 Gap。空 B 不生成占位 WAV。需要解码、SRC、位深/声道转换的格式明确拒绝，等待独立转换任务。

发布顺序：

1. 保存带冻结输入的执行任务意图；实际全量源复核发生在建立输出目录之前。
2. 排他 owned 目录、逐面编译/校验和进度持久化；文件属于该任务，不覆盖来源。
3. 在数据库记录期望 Manifest Hash；写清单、同步并重新校验文件、Hash 与目录归属。
4. 在事务中插入不可变执行资产，将任务标为 completed。

清单保存公开谱系、参数、配方、回执和相对输出文件名；私有源 locator/capability 只存在 Core 数据库。资产记录说明 `verified-at-publication`，不是当前文件仍可用的保证；`verifyExecutionAsset` 提供独立带时间戳的最新核验。

## 失败、取消与恢复

全局同时最多两项执行任务、两项只读核验；单草稿最多 100 个已完成/运行中/中断资产候选及 1000 条任务记录。每项读取、任务、恢复有最长 30 分钟循环期限；底层阻塞系统调用不承诺硬实时终止。

撤销源/目标授权会取消相关活动；用户也可独立取消读取而不撤销目录授权。取消、磁盘满、源改变和输出损坏保留有界失败原因，不删除文件。

启动恢复先将未完成任务标为 interrupted。只有完整的已发布文件、清单、Hash、归属和授权仍一致时才幂等补交数据库；不重编译。Direct 恢复不再读取原用户源文件；Prepared 仍需核验被引用的保留原件。不完整产物保留中断记录，不伪造成功。

历史任务和资产分别保存；已完成任务和资产禁止更新或删除。schema 11/12 与旧版本升级同事务执行，迁移失败不留下半套表或版本号。

## 桌面交互与边界

沿用录音草稿中的原生对话框，不添加设备页或永久侧栏。提供 Profile 版本、三态覆盖、临时链、冻结来源、目标、显式格式/帧数与确认，之后显示任务进度、历史及重新验证。

等待未知保存回执时保留原命令、禁用关闭并允许重试。读取和编辑分别处理；刷新失败后再次刷新保留未保存内容并要求重新确认。关闭有未保存编辑时要求明确放弃，关闭后焦点回入口。

本次只提供会话内原命令重试及持久化任务恢复，未实现通用跨 Renderer/应用重启 outbox。F-01、Archive Policy、Backend 认证、完整 Preflight、RecordingPlan、Attempt、设备排空/实体完成、归档去重/备份仍待后续。所有回执 `formalReady=false`；不播放音频、不自动清理，也不承诺永久自包含归档。

## 验证方式

单元与迁移测试覆盖不可变版本、CAS、幂等、事务回滚、取消/撤权、实际文件损坏、发布失败恢复、期限与磁盘满。真实 Electron Main/Preload/utility IPC 使用隔离合成源、目录和资料完成 Direct 与 PREP 双面/空 B 流程。最终 WAV 另由 Python `wave` 独立逐段核对。自动证据与真实 Source Roots、Roon、输出设备及 Owner 验收分别记录。

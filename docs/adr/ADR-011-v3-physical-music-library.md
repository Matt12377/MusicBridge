# ADR-011：原版发行版与历史录音同库展示

## 决定

实体音乐库是两类身份的聚合视图。原版 CD/磁带建立独立本地 UUID；历史自录内容绑定既有 Physical ID，通过只读联接进入同库，不复制库存。记录的类型不能因编辑而改为另一种介质。

原版允许基础/部分补齐/用户核实。核实是用户声明，不是自动识别证明；未填写版次不能声明已核实。曲目保留碟号或 A/B 面、位置和可选时长。旧录音内容只允许保存到已登记的 legacy recorded 副本，不允许把空白、预留或未知副本直接变成录音完成。

## 存储

Schema 2 → 3 在既有 SQLite 写锁内建立 `music_releases`、`legacy_recording_content`、`music_photos`、`music_ledger`。迁移失败整体回滚。原有库存、照片、账本和永久编号保留。

音乐资料与照片操作在同一连接内执行独立短事务，音乐命令 UUID + 规范化请求 Hash 实现本服务内幂等。账本不可更新/删除；修改采用 revision 检查。原版照片重复内容去重，最多 24 张，沿用受控原生选择与展示副本规格。照片表有独立发行版外键，不借用磁带型号 ID。

历史补录只增加资料和副本 revision，不改变数量/usage。库存详情只读投影 recordingTitle，保证两种入口展示同一盘录了什么。

## 接口与 UI

公开接口只提供有界查询、详情、保存原版、补录旧录音和照片操作；不暴露 SQL、路径、Roon 运行期 ID 或音频 URL。实体数据操作不依赖 Roon/Provider。

继续使用收藏中的两个视图；音乐详情可返回原型号/单盘，型号详情可进入旧录音内容。表单先展示基础字段，发行资料/品相/曲目折叠显示。照片使用等比展示，失败不影响实体记录。

## 下一层

TASK-052 接入稳定本地数字对象与用户确认的 Exact/Probable/Related 关系。此阶段一律显示 Roon 尚未关联，不把未匹配解释成 Physical Only，也不根据名称推断 CD Rip 来源。未来正式录音发布使用冻结 Master/Recording 身份，不复用 legacy 补录接口。

保存回执未知时 UI 锁定原命令供重试；跨应用重启的未确认操作 outbox 仍由后续恢复任务补齐。自动测试、真实库存/照片、Roon、硬件录音和 Owner 验收分别记录。

# ADR-039：Node 原子导出与 Rust v2 只读查询

状态：RUST-002 显式原型，生产默认仍为 Node。

RUST-001 证明了只读进程协议，但从公开完整页取得快照受每页 100 型号限制；自行提供 2,000 型号数组也不能证明活跃库的原子性。因此在 Node Owner 内增加一次同步读事务，复用现有批量水合和公开 DTO 验证，在当前连接和唯一作者中捕获完整状态。只有成功 boot 的 Owner 才可导出，前后工作库身份检查及回执身份绑定防止换库结果混入。

Rust 接收只读 DTO，不打开生产数据库；Node 的 208 命令、写入、凭据、Provider、Roon 与录音职责保持。快照是读取时刻的事实，刷新显式创建新端点和 snapshotId。超过 2,000 型号或 4 MiB 失败，不截断，也不跨时刻拼接分页。

查询投影采用协议 v2，公开 IPC 版本保持不变。Unicode NFKC、JS 空白和 JS 大小写在 TS 生成；Native 仅使用 SQLite 一致的 ASCII lower 与库存/年代谓词。这样无需引入另一套 Unicode 依赖或改变现有搜索语义。TS 还核验请求对应的筛选页，使形状合法但事实不符的回执也失败。Native 保留原 v1 无筛选合同，成功 prepare 绑定一种协议版本，防止进程中途降级。

新异步工厂等待既有已就绪 Node Owner，所有导出与启动步骤共享单调期限。撤销发布权不会关闭源 Owner或清除它尚在途的合法 RPC；只清理当前工厂创建的原生端点。没有自动重放、生产默认开关或真实库迁移。

差分 oracle 是真实 Node 两库的 SQLite 查询，涵盖 Unicode、字面百分号/下划线、年代、库存、组合条件及分页顺序。成本须包括导出、复制/序列化、二进制核验、进程启动、往返和 TS 校验。只在新鲜证据支持后报告性能收益。完整协议见 [v2](../contracts/rust-readonly-sidecar-v2.md)。

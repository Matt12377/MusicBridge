# Mousa 4.1 — 资料库渐进可用：实施边界

- 授权：2026-11-15 Owner 批准桌面端执行分阶段计划；iOS 由另一个独立会话开发。
- 桌面起始基线：`399f5ddc534a8baad9e857eb126a73a0a08cbcc4`，已核对原分支、工作区和 origin 一致。
- 实施采用四项线性任务，各自独立分支、实现提交、结果报告提交与普通推送；下一项从上一项最终报告 HEAD 创建。
- 原运行实例、真实资料库、账号、凭据、来源文件、手机安装与用户队列不作诊断或测试对象。

## 1. 独立设置与应用壳

窗口挂载、设置导航、外观和静态应用信息不依赖 Core、历史扫描核验、Provider 恢复或输出设备发现。仅原可信窗口的固定 app-info/theme IPC 可以提前使用；Core 业务、配对、目录管理、源写、播放和 outbox 变更仍拒绝准备期操作，不排队、不在稍后补发。原 remote bootstrap 偏好与唯一 Core 启动结算保留。设备、账号等状态未取得时展示未知/准备中，不冒充未登录或零曲库。依赖服务的子模块在准入前不挂载；已挂载模块的临时服务中断不得清空草稿。诊断导航始终保留。

## 2. 扫描提交到可浏览可播放的增量链路

保留现有扫描发现、有限解析、事务提交、唯一 DatasetOwner 和原播放 route。专辑查询批量最多 100；首批不足 100 也可发布。扫描提交事件与页面刷新合并、有界预取、可见封面窗口，不能逐文件重读全库。动态目录分页必须处理增长、去重、排序和失效，保留滚动锚点；不混用 dataset/epoch/query 代次。只有通过当前权威校验并已提交的记录可服务。部分专辑不冒充完整；新增曲目不自动改写当前队列。不更改旧 iOS HTTP 合同来获得桌面功能。

### 第二项落地合同

- 新增具名只读 `localAlbum.queryVersioned`，返回闭集 `{ revision, page }`；公开可选能力为 `queryLocalAlbumsVersioned`，原读端口可选能力为 `queryVersionedAlbums`。请求每页 1–100 张，修订为 64 位小写十六进制；原 `localAlbum.query` DTO 与 200 上限不变，iOS HTTP 不新增字段或必需升级。
- 页与修订在原 Owner、库存读屏障和 seal 内共同捕获，沿原前台资源包装、dataset/epoch 与原请求复核，不新建数据库 writer、Owner、快照事务或第二份整库 DTO。按封面筛选时库存修订进入成员身份，普通补图不导致整墙重排。
- 每页立即发布，下一 raw offset 按实际返回条数推进。增长或前插导致的修订漂移只去重合并并标脏；只有完整、修订稳定且未被事件标脏的一轮才删除旧项和规范排序。同一连续修订内的重复身份或计数矛盾拒绝，失败单页不推进 pass 状态。
- 未读完的一轮合并扫描/封面成员事件，继续尾部，不反复取消重读前 100 张；短轮与后台核对按约 1000ms 合并，普通下一页约 16ms。保留卡片期间明确显示“目录正在更新”，不把混合保留项写成当前完整总量。
- 五列墙只新增 opt-in 身份锚点。排序/删项后按新几何恢复同一可见专辑；用户主动滚动或容器改变时放弃旧锚点，不争抢用户滚动。
- 当前成长专辑的详情由原实际读口取得；旧显示摘要不是播放资格，不自动重建/追加队列或开始播放。壳、Core 准入和首次专辑上下文仍走同一条原控制流。

## 3. 安全冷启动与历史核验

先测量启动阶段、首批提交到展示、首个有效播放请求和冷/热缓存差异。基础数据库、身份、来源权限、关键恢复与不可分割的全局安全检查必须保留。按页/批提前发布须证明所需跨表、跨批依赖闭合，不能把完整验证简单放到后台后立刻放行。复用已验证检查点必须绑定内容和实现身份，不靠文件大小或 mtime 证明。缓存失效、升级、损坏和重启均需保护测试。不得通过缩小安全校验或删除历史记录来宣称性能达标。审计异常撤销相关能力，独立应用壳仍可使用。

### 第三项的内部边界

- 成对历史核验由独立启动审计服务组织，仍在原 Owner 的原保护事务内运行。缓存沿既有内容指纹、实现/runtime/schema 与物理身份校验；miss 则完整验证 catalog 与 scan。任一域失败或取消，清除两域派生证明，不把“目录已核、扫描失败”发布成部分就绪。
- 原 recording/来源/数据库基础检查、queue 检查、扫描与 attempt 关键恢复、唯一原 COMMIT 及 Owner 交付顺序不变。服务不提交、不创建活 Source 能力，不自行宣告 Core ready。
- 冷启动专用同步读 session 与语义验证拆开。只有持有原事务时，既有有界 batch JSON memo 才可在同一次完整核验内避免逐文件重复传输整批原文；每行真实 file-state、原 guard 与跨表/批关联仍完整验证。逐行与发布前实际读取 total_changes、data_version、主/临时 schema、user_version、foreign_keys 及事务状态，变化立即拒绝；取消沿原异常退出。
- session 的水位语句计入原 32 条语句总预算；原 memo 的 64 项、4MiB 原文及 32MiB 保守分配上限不增加。关闭或失败不续借 scope，不跨连接、跨核验或跨调用保留。普通核验、迁移与隔离备份/恢复仍逐项实读原 batch 原文。
- 这是减少原保护事务内的重复传输，不是删减历史、不做校验、mtime/大小捷径或把全局历史核验搬到后台后提前放行。独立壳仍可用；扫描与播放资格依旧由原服务权威决定。

## 4. 播放优先的扫描调度

原统一资源锁、来源许可、FD quiet 确认及唯一队列保持。起播/切歌/seek 优先，稳定播放的低预算扫描须有明确的资源资格和行为 Gate；预算不足或资源冲突退让，并显示真实的暂缓状态，不承诺无条件边播边扫。不扩大默认源写权限。

### 第四项的内部边界

- 新纯策略只返回调度上限：确认空闲沿用原可信组合的 1／2／8 槽；前台操作、未确认的媒体活动或失观测为 0；同一原播放代的合格所有权连续稳定 2000ms 后最多 1 槽。首次从未观测显示／媒体活动且没有可用 Zone 连接时，保留原空闲扫描，不要求先连接设备；已有活动后失联／未知不借用这项初始资格。生产 Core 原空闲组合仍为 2 或 8；不是按 UI 的 playing 字段授权，不新增队列、writer、计时器或来源能力。
- 合格播放复用 Controller 的原显示关键期、原所有权及代次，还须无原 NEXT 准备在途。网关仅在没有实际媒体请求，或唯一实际请求精确属于当前 token 且已观察到首批 pipeline 字节时证明资源资格；预解析、preflight、仅响应头、并行请求及不明归属都封闭。字节观测不是设备已收到或实际发声证明。
- 网关的实际请求开始、首字节和结束均重建稳定窗；起播、切歌、seek、暂停／恢复、停止未知及关闭通过原操作标记同步封闭。即使当时没有扫描票据也采样，不能漏掉零票据期间的前台操作。NEXT 标记只等自身实际工作退出；中断清理仍沿原异步路径，未知 dispose 不伪归零。
- 唯一 Node Core↔Owner 私有通道新增空请求 `scanReadBudget`，闭集结果为 `{ concurrency: 0|1|2|8 }`；沿原 readiness、epoch／dataset 和反向帧校验，不进入公开 dataset／Renderer 命令或 iOS HTTP。结果是最大调度窗口，**不是剩余空槽或 Source 读许可**；不得减去扫描自己的在途票据，否则原定时部分提交会自取消。
- 原 `scanReadStatus`、acquire／watch／release 的线形不变。逐读 acquire 同时执行原总容量和动态 scan 上限，旧已撤销票据仍占槽到原真实 quiet 之后 release；显示目的保留原准入。预算缩小会撤销旧 scan 票据，不通过改计数、伪造 FD 关闭或 kill 共享 Rust pool 让新工作提前进入。
- 原 Coordinator 每个发现窗口与原 revalidation 取冻结资格和 Core 提示的较小值，不改持久冻结设置；只有有效八槽窗保留原 CUE 八槽预读。运行时提示变旧不构成授权，逐读仍须原票据和统一 Source claims。非法回执 fail closed，不猜并发，不把取消写成坏媒体。
- 预算 0 时沿原 media-busy 暂缓语义，恢复探针先问预算，再触碰来源目录；不以周期性 resume→pause 反复改 job revision。原手动暂停／取消、取消中的 join、恢复 COMMIT 与来源代次保护优先，不自动重开手动停止的任务。
- 不新增前台控制的异步 quiet 屏障，不修改 Rust parser 或源写授权；仍由原协作取消及实际 read settled／FD close 确认收口。稳定窗是保守调度规则，不是对真实存储、账号、设备、听感或录音负载的性能认证。

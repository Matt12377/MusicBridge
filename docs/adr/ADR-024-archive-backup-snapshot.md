# ADR-024：一致性快照与显式归档内容备份

状态：TASK-064 本地实现候选；恢复激活和桌面工作流待 TASK-065/066。不是 F-01、完整 Gate E 或 Owner 接受。

## 决策

使用 Node 22.23.2 内置 `node:sqlite` Backup API 从仓库持有的连接生成快照，禁止对活动主数据库/WAL 分别复制。快照写入空的能力目录，并把独立快照切为 DELETE journal，完成 integrity_check、foreign_key_check、fsync、Hash 后才交给内容备份。所有路径只在 Core 内部流动，没有新增任意路径 IPC。

仓库 close 立即阻止新读写，已有快照保持连接至异步 Backup API 结束；不在备份期间提前销毁连接。后续 UI 取消会阻止内容复制/完成发布，但 SQLite Backup API 本身不承诺立即中断。大库的运行时进度与取消交互在 TASK-066 接入时另行验证。

备份范围只从快照读取：已完成操作、M/L/执行身份、Manifest、对象和关系闭包必须吻合。活动数据库仅用于复制前后的权限撤销检查，不重新枚举业务范围；因此备份开始后新增归档不会混入旧快照。当前 schema14 含库存、照片 BLOB、母版、PREP 与执行/归档元数据。

## 范围声明

- `metadata`：数据库和已完成操作 Manifest、内容索引。不复制归档音频；允许原归档离线。未完成操作 ID 明确列出，不把它们变为完成。
- `archive-content`：同上，加全部已完成归档引用的实际 Content Objects；跨操作相同 Hash 只复制一次。所有已完成引用逐项验证，存在未完成归档、缺对象、Hash 不符或撤销权限时不发布。
- 两者都不是操作系统/账号备份。未归档的源、Logic/执行工作副本和 Provider 凭据不在声明范围。Reference Dependent 历史仍不获得“精确源齐全”承诺；F-01 未决定，不自动清理内容。

## 文件边界

原生授权在 TASK-066 承接。本切片调用方必须明确持有目的能力、稳定任务 ID 和 userConfirmed。目的目录与 Source Roots、工作目录、归档目录不能重叠。任务目录用 mkdir 排他创建；目标文件使用 O_EXCL / O_NOFOLLOW 与 0600，目录0700，不覆盖已有文件。复制使用既有只读完整 Hash 文件流，目标重新校验后 fsync。

完成前保留隔离目录。`Backup.json` 描述确切范围，`Complete.json` 绑定其 Hash；验证器必须同时重新检查 SQLite、清单关系、每个 Manifest 和声明的内容字节，不能只相信完成标记存在。中断和磁盘满可能留下不完整目录；当前不自动删除、不自动覆盖重试。恢复和持久幂等 UI 将在后续任务使用显式策略处理。

只验证本地单应用写入文件系统。目录能力与 inode 校验不能提供针对同用户恶意并发替换文件的操作系统隔离；不宣称支持多进程共写、任意 NAS 或未测试卷。

## 恢复边界

验证备份包只读取包内文件，不触及快照保存的绝对路径，也不激活源/归档/工作目录权限。TASK-065 必须隔离恢复、重新授权真实位置、处理当前数据冲突并验证第二次恢复不覆盖新数据。当前任务不能关闭 Gate E-12～E-14，也不能把旧文件系统 inode 当作新机器权限。

## 依据

- [SQLite Backup API](https://www.sqlite.org/backup.html)：使用一致性数据库快照，外部文件由应用自己的协议保证。
- [Node SQLite Backup API](https://nodejs.org/api/sqlite.html)：API 自 v22.16.0 可用；目标已存在会覆盖，因此本实现先排他创建空目标。

## 验证计划

WAL 数据和账本一致性、快照后新写隔离、异步 close、既有文件/链接保护；真实合成档案对象完整复制、离线独立核验、元数据不冒充音频备份、快照后新归档排除、缺失/改变/撤权/未完成拒绝；磁盘满复制故障和复制期间撤权；跨操作去重、照片 BLOB 与库存快照；篡改清单即使重算顶层 Hash 仍被数据库引用闭包拒绝。自动验证只用合成数据。

# ADR-026：独立维护账本、显式备份恢复与工作库激活

状态：TASK-066 本地自动验证通过，保留容量与Owner验收边界。基线 TASK-065 abbd2fc；不包含完整 Gate E、F-01 或 Owner 验收。

## 决策

- 在应用私有数据目录使用独立 `backup-maintenance.v1.sqlite`，与 collection 工作库分离。授权、命令回执、备份/恢复任务和激活意图不能随恢复旧快照而回滚。受信任的 utility 组合层注入文件位置；Renderer 只持有不透明 ID、有界摘要和状态。
- 原生选择只授予所选目录能力，不立即备份/恢复。每次写入都须确认范围和目标；请求包含稳定 commandId。幂等回执拒绝同编号不同操作/参数，不自动覆盖、删除或重新执行失败目录。
- 后台单队列使用 TASK-064/065 的实际文件核验与隔离复制。验证、索引重建同样可查询取消。终态不可被晚到成功或取消改写。冷启动将未终结的任务标为 interrupted，保留所有文件；不自动续写、不恢复目录权限。
- 恢复必须引用成功验证的备份身份，并在复制前重新核对。元数据备份不声明音频可用。基本索引的未知历史和 Quarantine 以计数和问题项保留，不生成库存或完成事实。
- 完成备份的应用自建子目录可加入已授权备份来源，便于立即复核；生成隔离恢复候选不切换当前库。恢复后的历史绝对路径与不可变记录保持原样。实际内容新位置通过独立绑定解析，不删除触发器改写历史。

## 激活边界

位置绑定与当前工作库切换单独确认，明确停止当前播放、丢弃未保存录音编辑及重启 Core 的影响。维护库 schema v2 与旧 v1 回执兼容迁移，使用同一排他 SQLite 连接持久记录激活意图和当前库指针；同进程及跨进程不能同时运行维护写入者，进程退出由系统释放锁。

1. 激活请求同时绑定恢复任务、预期当前工作库、写入确认和停止播放确认。确认先记为 preparing，后台复核恢复候选，排他复制数据库至应用私有 `restored-datasets/<activation-id>/database`，不修改恢复包或原工作库。只有独立完成标记及字节复核成功才记 prepared。
2. Main 收到 prepared 后停止播放并重启 Core。新进程把 prepared 记为 activating，复核恢复任务、目标授权、新旧目录边界、候选文件和数据库，再创建 Runtime。Runtime 启动成功后、发布 Core ready 前，在同一事务切换指针并记 active。失败回执与所有候选文件保留，不覆盖重试。
3. 冷启动发现 preparing 表示准备中断，记 failed；发现 activating 表示上次启动未完成提交，记 rolled-back 并使用先前工作库。已经 active 的工作库允许正常业务变更，后续冷启动不能用首次复制 Hash 拒绝它的新数据，也不能自动恢复旧目录权限。
4. 内容位置绑定保存恢复包能力和清单指纹，按 operationId、rootId、manifestHash 匹配不可变历史。完整内容备份通过新恢复位置读取对象并重新校验；未绑定的新归档仍检查原授权。元数据恢复不声明音频可用。旧 archive root 的 revoked 状态及历史绝对路径保持原样。
5. 旧索引聚合回执没有问题明细时，迁移为零条明细与真实省略数量；界面保留未知事实和 Quarantine，不凭空补齐历史。详细问题只投影有界的 code、ID、Hash，不公开内部路径。

上述协议已通过文件、事务、再次备份、桌面整链路与真实合成子进程 SIGKILL 验证。候选 Gate、审查及精确身份见 TASK-066_RESULT；这些证据仍不能代替真实用户恢复与 Owner 接受。

## 验证

保留每一段 RED/GREEN 日志；最终按 SPEC、QUALITY、全量 Gate 与候选身份收口。合成文件和 SQLite 证据不能替代真实用户恢复或 Owner 验收。原有 V2 与 TASK-047/061 等历史条件不变。

容量边界：普通冷启沿用2秒ready，完整数据库检查与prepared大内容复核的规模耗时未测，可能有界失败/回滚；TASK-078/Gate E补齐容量矩阵并统一超时策略。当前小规模合成通过不能替代此项。

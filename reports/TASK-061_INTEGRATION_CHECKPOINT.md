## 本次实现

1. 公开选择区分四条路径：旧 Direct、原始 PREP 引用、明确 Direct 转换、独立 PREP Derivative。V2 计划与实际回执使用独立 schema；不把预计帧数当成完成事实。
2. Core 将逐曲转换文件、最终逐面文件、清单写入任务独占目录。所有中间转换文件都进入发布清单和空间预算；取消、撤权、失败不覆盖、不自动删除，不在重启时重放转换。
3. 发布后的数据库提交失败可以只核验并补交，Direct 不需要再读取用户原源。PREP 派生继续核验所保留原件，原件授权和谱系不被省略。损坏的中间文件也会使资产不可用。
4. PREP 位深来自实际保留 Render 探测，独立生成 Derivative，不覆盖原件、不重新插入 Gap；Master/Layout/PREP 仍不可变。
5. 运行时只接受受信任 Core 组合层注入的转换器对象。不新增 Renderer 可选可执行路径、命令参数或系统 PATH 搜索。普通产品启动仍未配置转换器，转换预览会明确拒绝；本机 Homebrew 未默认启用、未打包。
6. 桌面增加明确转换选择、预算、预计帧范围、源技术信息与 Hash、精度/SRC/Dither、固定构建身份，切换输入会撤销旧确认。原有进度、取消、原命令重试、历史与重新验证保留。启动 PREP 派生包含原件读取，因此使用既有有界长文件请求期限。

SQLite 仍为 schema 12：既有表和列未改，新增数据由配方/清单 schema 2 区分。旧 V1 合同继续读取；历史文件清单的额外音频字段不参与新文件集合匹配，但其原清单内容仍参与 Hash。新写文件清单只保留相对名、大小、SHA-256。

## 实现范围

1. 正常桌面启动使用官方发现/配对，历史“自动 SSH”偏好不再启动隧道；SSH 保留为显式手动回退。目标持久化兼容固定 SDK 的冷启动行为，保留官方主动 Pair；授权 token 映射未改。
2. 可信桌面入口经同进程 Utility 参数启用媒体能力。配对 socket 给出明确私有 IPv4 后才绑定该本地接口的随机可用端口，监听成功才公告；准备中拒绝远端 URL。环境变量、Renderer、公开 IPC 不具备启用入口。
3. 独立媒体监听只接受精确 Core peer 的本地歌曲、已登记网易云歌曲、固定 PNG 的 GET/HEAD；拒绝子网放宽、health、SVG、query、绝对请求地址及错误原文。控制/账户/诊断和原 Gateway 继续回环。
4. 换代、取消配对、退出同步撤销旧公告并关闭自有连接，迟到监听及 SDK 回调失效；重绑不永久关闭本地租约注册器。媒体准备成功才开放 Core 播放。
5. 原诊断 ring 分别记录停止旧会话、会话建立、play 派发、HTTP 请求、首个非空音频块及本次 Playing。保留原独立 50 条本地阶段 ring；不以 HEAD、图标、旧 Zone、迟到回调或 Promise 结束替代播放证据。

未重写队列、歌词、曲库、录音或音频文件。没有迁移源目录、修改音频标签、变更输出 Zone 或用其他音源替换当前曲目。

## 真实 Mac + mini

普通桌面入口、真实 NAS 文件与已配置网易云账户；没有使用合成数据代替实播。目标 Core 为 mini，输出 Zone 为原 Studio Display。

| 场景 | 第一轮 | 重启复测 |
| --- | --- | --- |
| NAS：陈奕迅专辑第三首《多少》 | 本次 Playing 130 ms，返回 33,719,686 字节 | 本次 Playing 50 ms，再次持续推进 |
| NAS：定位至曲末并自然续播第四首 | 第四首 Playing 180 ms，返回 20,147,871 字节 | 未重复此项；复测了第三首到网易云切换 |
| 网易云：Klinn《Fallen（秋日-凋零）》 | 本次 Playing 54 ms，返回 16,644,151 字节，2,621 ms 完成 HTTP 传输 | Playing 47 ms，相同字节数，2,808 ms 完成传输 |
| 暂停/恢复 | NAS、网易云均取得实际回执 | 网易云再次暂停；定位回 0 后推进至 27 秒 |
| 结束/切换 | NAS 切到网易云；网易云自然结束返回 idle | NAS 到网易云再次切换成功 |
| 配对/端口恢复 | 精确配对媒体入口；普通播放无 SSH 进程 | 不重新配对，使用新随机端口；旧端口关闭 |
| 正常退出 | 退出 0，无强杀 | 暂停会话下退出 0，无强杀 |

表内毫秒是 Adapter 本次启动到真实 Playing 回执的耗时，**不是点击到出声的总延迟，也不是 P95**。HTTP 字节是本机 pipeline 证据；主观听感不代替 Owner 验收。

mini 两次读取固定 PNG 均为 200、68 字节，耗时约 3～4 ms；mini 访问 Mac 的控制端口失败（curl 退出 7，属预期边界结果）。实际 Roon 媒体请求只能通过精确 peer 检查后进入原传输链。

本地真实 Roon 请求在本次窗口为完整 GET，Core 缓冲完成后可内部定位，没有凭空声称发生额外 HTTP Range。原 Range 行为已通过真实自有合成文件的 LAN HTTP 206 与原本地租约回归验证。UI 操作包括打开曲库、第三首播放、暂停恢复、定位、续播、在线切换、诊断及返回；未操作手机。

最终 `edcdd845` 再次通过普通桌面入口启动并实播：导出同时包含 `roon_core_paired`、当前 Core 的 `roon_zones_subscribed`、同一媒体身份的正字节和 `Playing`（50 ms）。该轮网易云返回 16,644,151 字节、HTTP 传输 2,511 ms，持续推进后在约 1:24 暂停；未见 ROON_TIMEOUT。新版保持运行且已暂停，未操作手机。

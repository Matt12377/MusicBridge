# 磁带参考图覆盖补齐

## 身份与范围

- 基线：`f7f7bd165f091ab8c1d47274efa42ce69cd1ff85`。

- 本轮处理已授权参考书的漏图、明确名称差异及遗漏目录条目；不改库存身份、数量、实物照片或持有关系，不扩大至外网搜图、播放协议、硬件或容量链。

## 根因与实现

首批图片提取覆盖标准独立型号面板，但遗漏多型号拼版与年表中的小图。原精确型号匹配不能读取库存中的长度、颜色和拼写别名；不应通过全局删除后缀或模糊匹配扩大覆盖。

1. `CanonicalReference.imageAliases` 为可选有界字段，每项带品牌、型号和核对说明，每条参考最多 16 个；拒绝空说明、未知字段、重复别名和超限数组。
2. 收藏参考图可读取明确登记的别名；类型、格式、年份和版次约束继续生效。别名不改变参考身份、不写库存、不建立持有匹配。
3. 规范化比较包含别名，冲突不静默丢弃；深复制防止规范化结果与输入共用可变别名对象。
4. 从原扫描书人工核对、逐格裁剪缺图，并补入有明确书页证据的目录漏项。年表未单列年份的图仅标记为型号参考；不制作替代图片。

## 本地实际导入

- 发布前使用 SQLite Backup API 保留一致备份，源数据库仅只读检查。
- 在实际应用中载入配图 JSON，预览确认新增两个有书页依据的目录项；移除、合并、拆分均为零。经既有独立确认及 Main outbox 发布，界面显示“目录修订已发布”。没有直接写数据库，没有在等待回执时重复提交。
- 发布后只读校验：八张库存/实物/照片表及原始来源逐行不变；两版历史目录完整不变；新版本全部条目与核准稿相同；已有参考图片未被替换。quick_check 与 foreign_key_check 通过。
- 使用真实 Renderer 匹配函数对已发布数据计算覆盖，与人工核对清单一致；旧的同型号漏图组已全部获得参考候选，未证明的变体和类型冲突保留占位。
- 实际收藏墙截图可见新增参考图、多版候选及名称别名生效；图片注明“书籍参考 · 版次未核”，原库存名称仍保留。
- 当前生产构建的开发版已启动供人工查看。快捷键未使旧进程退出，第二实例被单实例保护拒绝；确认旧实例空闲后仅对该 PID 发送 TERM，再启动成功。此过程不记为普通 Quit 验收通过。

个人库存、图片、扫描文件、本地路径、核对表及数据库回执均留在仓库之外。公开测试仅使用合成数据。

## 剩余边界

本书没有找到对应图、特定变体缺少依据或磁带类型冲突的记录，已逐项列入本地剩余清单，不以相近型号补位。参考图不是实物照片，也不确认库存具体版次。代码及报告推送至评审分支；merge、release、签名公证、真实播放和 Owner 最终接受不在本轮完成声明内。
